## Key patterns

* **State/DI:** `#[derive(Clone)] AppState`; `MySqlPool` already `Arc`-interned. Feature routers generic over `Router<AppState>`. Composition root = `build_state()`. Cross-feature rule: feature stores call `common::ownership` + `common::card_summary` + `common::label_seed` + `common::validation` helpers; features never import each other's stores (kills the `Boards↔Columns↔Cards` triangle). FKs are `Option<i32>` / newtype IDs (`Option<UserId>` etc. — never `i64`; schema is `INT`↔`i32`). Store fns are generic over executor: `E: Executor<'e, Database = MySql>` if `MySqlExecutor` is unavailable in sqlx 0.8 — verify the bound name at T03 and use one form everywhere. Newtypes derive transparent sqlx `Type` (`Encode`/`Decode`) + serde transparent + `ToSchema(value_type = i32)`; bind via the newtype (no `.0`-at-every-site fallback to raw `i32`).
* **Hexagonal, pragmatic:** `routes → store → MySQL`. Web-error rendering (`AppError → IntoResponse`) lives in `error.rs`; the error enum core carries no `axum` state beyond the `IntoResponse` impl (pragmatic coupling — do not claim "domain has zero axum dep" unless the core is split). Domain has no `axum` extractors. One ownership-check helper per aggregate. Mocks: pure position-math only (`clamp_position(requested, len)` + gap-computation helpers — the named unit subjects after the A3 set-based retirement); all DB behavior via `#[sqlx::test]` real DB.
* **Error:** `enum AppError{NotFound,Unauthorized,Forbidden,Conflict,Validation(garde::Report),Json(JsonRejection),PathRejection,QueryRejection,Db(sqlx::Error),Timeout,Internal}` (`thiserror`-only; `anyhow` only at the `main()` boundary; `Internal` is a unit struct) + `IntoResponse` rendering `application/problem+json {type,title,status,detail,instance,errors?}` where `type` is a stable URI per error from the registry below (never `about:blank`) and `instance` is always set (`"{METHOD} {path}#{x-request-id}"`). One shared `pub(crate) fn problem_response(status, type_uri, title, detail, instance, errors)` constructor in `error.rs` — `AppError::IntoResponse`, the governor 429 handler, and `AuthSession` rejection all call it (identical shape). `Db(sqlx::Error)` maps by matching the *inner* error (not one-status-per-variant). `handle_timeout` returns `AppError::Timeout.into_response()` (single 503 renderer). Log full `sqlx::Error` with `tracing::error!` server-side (`IntoResponse` logs before rendering), expose generic 500. Follow Axum `examples/error-handling`. `JsonRejection` is `#[non_exhaustive]` — keep a catch-all arm. Type-URI registry: `validation-error→400`, `invalid-json→400`, `invalid-path→400`, `invalid-query→400`, `unauthorized→401`, `forbidden→403`, `not-found→404`, `conflict→409`, `rate-limited→429`, `service-unavailable→503`, `internal→500` (all `https://kanpad.dev/problems/<slug>`). Mapping table:

  | Source | Status | Note |
  |---|---|---|
  | `JsonRejection::MissingJsonContentType` | 415 | Wrong/missing content-type. |
  | `JsonRejection::JsonSyntax(_) \| JsonDataError(_)` | 400 | Malformed JSON / serde type error. |
  | `JsonRejection` catch-all (`_`) | 400 | Forward-compat with new variants. Body-size-limit (Axum `DefaultBodyLimit` 2MB) routes through the same arm — confirm in T04, record decision. |
  | garde `Report` | 400 | **Parity** (verified 2026-10-11): Nest's per-endpoint `ValidationPipe` emits 400 today on mutations except auth register/login (no pipes there); never 422. The `errors[]` field→message extension is new. |
  | `PathRejection` / `QueryRejection` (Axum 0.8 splits them) | 400 | Both mapped to problem+json (Axum's default 400 body is plain-text — wrap it). |
  | `sqlx::Error::RowNotFound` | 404 | Foreign IDs → 404 (no oracle). |
  | MySQL `1062` duplicate | 409 | Email / unique-label collisions. |
  | Pool acquire/timeout, connection refused | 503 | Readiness-gated; implies `/ready` also red. |
  | `tower::timeout::error::Elapsed` via `HandleErrorLayer` (above `TimeoutLayer`) | 503 + `Retry-After` | Origin timeout is 503 (504 is proxy semantics). `TimeoutLayer` alone never reaches `IntoResponse` — the handle layer converts to problem+json. |
  | Everything else | 500 | Generic detail only. |
* **Validation:** `garde` + `axum-valid` (`Valid(Json<T>)` / `Valid(Query<T>)` extractors; `validate()` → `AppError::Validation` → **400** problem+json with `errors[]`). Only `PaginationParams` + `AuthSession` stay custom extractors: `PaginationParams` does manual strict checks (`page≥1`, `1≤limit≤100`; out-of-range → 400 with `errors[]`, NO clamp — same shape, not a garde derive; `page`/`limit` ranges live here, not in the garde catalogue) + `AuthSession` custom. Rationale (verified 2026-10-11): the source has no global pipe, but per-endpoint `@UsePipes(new ValidationPipe({transform:true}))` exists on ~20 POST/PATCH handlers (NOT on `POST /api/auth/register|login`) → mutations except auth are already validated with **400** responses; garde is near-parity for those mutations and intentional hardening for auth inputs + GET query DTOs (mostly unvalidated in Nest — a new strictness the frontend migration must audit). Serde keeps **ignore-unknown-fields** (no `deny_unknown_fields`) to match Nest behavior (unknown keys dropped, never rejected — the per-endpoint pipes lack `whitelist`, so Nest passes them through too). **400-vs-422:** all validation failures return `400` problem+json with an `errors[]` field→message extension — matches Nest's 400 status; recorded in `20-api-contract.md` + `CONTRACT-CHANGES.md`. Field mappings: password strength `≥8 + digit/symbol` is **register/create-admin only** + custom **byte-length** cap `password.as_bytes().len() <= 72` on all password inputs (garde `length` counts chars; bcrypt truncates bytes — multibyte would silently collide; never bare `MaxLength(72)`); **login = non-empty + byte-cap `≤72` only** (never strength — legacy weak passwords must still reach 401, not 400); email via garde's email validator (approximates validator.js `isEmail` — borderline addresses may differ, note in `CONTRACT-CHANGES.md`).
* **AuthN/Z:** `tower-sessions` cookie + the **in-tree** MySQL session store (`common::session_store::MySqlSessionStore`, see Sessions below) — the store crate was dropped in T65, because it pinned `sqlx ^0.8` + `tower-sessions-core ^0.14` and blocked both dependency majors. `AuthSession: FromRequestParts` → `{user_id,email,role}` or 401 problem via the shared `problem_response` constructor — mirrors the stricter `CurrentUser` shape (`userId+email+role`). Session payload trusted without per-request DB lookup (same as Nest's `@CurrentUser()`), **except role-sensitive paths (`GET /api/v1/auth/me` + any admin route) MUST re-lookup the user row** (deleted → 401, demoted → 403) — this closes the stale-admin window; sliding-only renewal otherwise is accepted and recorded in `CONTRACT-CHANGES.md`. Ownership baked into SQL (`…WHERE board.user_id=?`); 404 for foreign IDs (no oracle), 403 only for role denial, 409 for state conflicts. Hashing: Argon2id (`argon2` crate, `m=19MB,t=2,p=1`, cost gated by `Settings.hash_cost`) for new passwords; **hash BEFORE tx.begin()** (tx holds only INSERT user + single multi-row INSERT labels); login tries Argon2 verify → on miss tries bcrypt verify (old cost-10 `$2a/$2b$` from `auth.service.ts:41-42`) → on bcrypt success rehashes to Argon2 + updates the row in the same request. 72-byte cap is new-password validation only; bcrypt fallback truncates to 72 bytes before verify (Nest/bcryptjs semantics). Unknown-email path runs a dummy Argon2 verify against a static PHC at current params (bcrypt timing delta accepted one-release). Keep `email.trim().to_lowercase()` + `REGISTRATION_ENABLED` gate semantics. Registration (`POST /api/v1/auth/register`) and `create-admin` both call the single prod helper `common::label_seed::ensure_default_labels(tx, user_id)` (`INSERT ... ON DUPLICATE KEY UPDATE` / `INSERT IGNORE`, MySqlExecutor-generic) + shared validators in `common::validation` (single email + password fns) — labels exist for every new user regardless of entry point.
* **Config/obs:** `dotenvy + envy` once at boot (see Config below); `tracing+EnvFilter`; middleware stack in fixed order (see Middleware below); `#[tracing::instrument(skip(pool, password, secret))]` — never log secrets. Secrets in `secrecy::SecretString` + `zeroize`; length checks on **bytes**.
* **OpenAPI:** `utoipa 6 + utoipa-swagger-ui 10` (**`utoipa-axum` is REMOVED** — 0 references; the spec is built with `#[derive(utoipa::OpenApi)]` in `docs.rs`); `#[utoipa::path]` per handler, `ToSchema` per DTO, one `ApiDoc` in `docs.rs`. ## Sessions (tower-sessions 0.15, in-tree store, fresh store-owned schema)

* **Store-owned session table, not Nest's table.** The baseline creates a store-owned `sessions` table **in the app database** (fail-fast `CREATE TABLE`, no `IF NOT EXISTS` — it is per-database, so there is no cross-process race). The app does NOT call any store's `migrate()` at boot — the baseline owns the schema. **2026-10-22: the store is now IN-TREE** (`src/common/session_store.rs`, implementing `tower_sessions_core::SessionStore` over the app pool) and the table's DDL is **unchanged** (`id CHAR(22) PK, data BLOB, expiry_date TIMESTAMP(6)` + `IDX_session_expiry_date`; **MessagePack** payload) — so this is a code-ownership change with no data implication, and the migration runbook's step 5(d) schema-drift gate stays green. `tower-sessions-sqlx-store` was removed because it required `sqlx ^0.8.0` AND `tower-sessions-core ^0.14.0`, which made **both** dependency majors (`sqlx 0.9`, `tower-sessions 0.15`) unreachable — see `54` Part C §C4. The store's expiry is a **timestamp** (not epoch-ms) and the store's own SQL is scoped by `WHERE id = ?` (the standing rule: never a global DELETE/UPDATE on `sessions`). `AppState::with_pool` derives the schema from the pool's connect options, so the store always follows the pool's database (one place; no `SELECT DATABASE()`). **Nest's singular `session` table (public schema) is NOT renamed and NOT in the baseline** — no collision (different name + shape + codec); it is abandoned at cutover (rows are ephemeral; drop or leave). Old rows are unreadable by the new codec + new `SESSION_SECRET` → **force re-login**: a `connect.sid` cookie signed with the pre-cutover secret fails HMAC verification → treated as anonymous → 401 → login screen (this is the T11 proof test). Do not write a row-migration; document the break.
* **Lifecycle:** `Expiry::OnInactivity(time::Duration::hours(24))` (sliding 24h, matches Nest TTL — note: tower-sessions uses the `time` crate, not `std::time`/`chrono`). The expired-row sweeper is **`store.continuously_delete_expired(tokio::time::Duration::from_secs(60))`** — a method on the *store* (ExpiredDeletion trait), spawned as a `tokio::spawn` task **only in `main.rs`** (never in `lib::create_app` — tests would leak a task + conn per test) with an `AbortHandle` wired into graceful shutdown (per the store README pattern; NOT on `SessionManagerLayer`). `session.cycle_id()` on register + every login **and** privilege change (fixation defense; register establishes an authenticated session too). No absolute expiry cap by design (sliding 24h renews under activity) — stale-privilege risk is closed by mandatory re-lookup on me/admin routes (see AuthN/Z).
* **Cookie:** `name = "kanpad.sid"` in dev/test, `__Host-kanpad.sid` in production (`Secure + Path=/`, no `Domain`), `http_only(true)`, `same_site(Lax)`, `secure(APP_ENV == "production")`, `path("/")`. **The `connect.sid` name is retired (2026-10-22)** — it was express-session's default, copied from the Nest source (`backend/src/main.ts:39`); a Rust service must not name its session cookie after an Express middleware. The `__Host-` prefix is kept because it is load-bearing hardening (host-only binding ⇒ no subdomain fixation; mandates `Secure`; mandates `Path=/`), and it stays **environment-conditional** because `__Host-` mandates `Secure`, which browsers only transmit over HTTPS — the plain-HTTP staging box in `docs/data-migration-live.md` therefore requires the un-prefixed name. **`__Host-` invariant is test-locked, not merely documented:** production `Set-Cookie` MUST start with `__Host-kanpad.sid=` and carry `Secure` + `Path=/` + `HttpOnly` + `SameSite=Lax` and MUST NOT carry `Domain`; dev/test MUST start with `kanpad.sid=` and MUST NOT carry `Secure`; **no environment may emit `connect.sid`** (regression guard). A future `.with_domain(...)` call must break a test, not production. `SESSION_SECRET` as `secrecy::SecretString`, ≥ 32 **bytes**, validated at boot; rotation = restart with new secret (all sessions invalidate — accepted). T11 asserts the cookie-attribute matrix per env.

## Middleware order (outermost → innermost)

Order is load-bearing. Canonical order (first listed = outermost; this list wins over any shorthand elsewhere):

1. Secure-headers `SetHeaderLayer`s (replaces `helmet(csp:false)`): `x-content-type-options: nosniff`, `x-frame-options: DENY`, `referrer-policy: strict-origin-when-cross-origin`, `served-by: rust`. No CSP header (matches `csp:false`). Outermost so 429/503/404 error responses carry them. **2026-10-22 amendment:** the Nest-era "no CSP" decision was made when the *Nest* service did not serve the SPA; the Rust service **does** (`ServeDir public/` + SPA fallback), so it is the origin that loads the frontend's scripts and styles. A CSP is therefore added here: `default-src 'self'; script-src 'self' 'sha256-<hash>'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self' <CORS allowlist origins>; frame-ancestors 'none'; base-uri 'self'; form-action 'self'`. `script-src` keeps neither `unsafe-inline` nor `unsafe-eval` — that is the load-bearing part; `style-src 'unsafe-inline'` is required (the frontend uses 12 inline `style={{…}}` React props). **Two corrections, verified against the frontend on 2026-10-22:** (1) `connect-src` MUST include the **CORS allowlist origins**, not `'self'` alone — in the dev topology the SPA at `http://localhost:5173` calls `http://localhost:3001` cross-origin (`frontend/src/lib/api/client.ts:67`, `frontend/vite.config.ts:27`), so `'self'` alone would have the browser block every API call; (2) `script-src` MUST allow the **inline theme bootstrap** in `frontend/index.html:12-21` — it is allowed by **CSP hash** (`'sha256-<base64>'` over the exact inline script bytes), and the hash is **computed at boot from the served `public/index.html`** (never a hand-maintained constant: a stale hash breaks the theme silently) with a test that recomputes it, so drift fails a test rather than the page. A per-request **nonce** is still out of scope (the static SPA fallback does not template the HTML), but a **hash** covers the one inline script that exists. `/swagger-ui*` is excluded from the CSP (a developer surface, not the SPA).
2. `SetRequestIdLayer(x-request-id)` — so even early rejections carry an ID. Use an `instance` field (`uuid7`/counter) per replica for log correlation (distinct from problem+json `instance` = `"{METHOD} {path}#{x-request-id}"`).
3. `TraceLayer::new_for_http()` with request-ID + method/uri/status latency; **redact sensitive headers** (`authorization`, `cookie`, `set-cookie`) via a custom `MakeSpan`/`on_request` filter — never log session cookies. **2026-10-22 amendment:** handlers must also skip the request body + session from their spans (`#[tracing::instrument(skip(state, auth, input))]` — `skip(state)` alone records `auth.email` and the DTO body, i.e. card `title`/`description`, via their `Debug` impls).
4. `PropagateRequestIdLayer(x-request-id)` — echoes the ID back to the client.
5. Restrictive `CorsLayer` (see below).
6. **Cross-origin check on mutating requests** (2026-10-22) — CSRF defence-in-depth, via `tower-http` 0.7's **`CsrfLayer`** (the Go 1.25 `CrossOriginProtection` algorithm); see the CORS section. Sits **inside** `CorsLayer` so a CORS **preflight** (`OPTIONS` + `Access-Control-Request-Method`) is short-circuited by CORS and never reaches it.
7. `CompressionLayer` — after Governor (never compress 429s). Note parity delta: tower-http compresses all response sizes (Nest's `@fastify/compress` used a 1024-byte threshold); accepted, no threshold config needed.
8. `HandleErrorLayer(handle_timeout)` + `TimeoutLayer(30s)` — bounds handlers; `handle_timeout` returns `AppError::Timeout.into_response()` → **503** problem+json with `Retry-After` (origin uses 503/408; 504 is proxy semantics).
9. `SessionManagerLayer` (innermost of the shared stack, closest to handlers).

`CatchPanic` (if added) sits just inside `Timeout`. Static-file serving (`ServeDir`) is outside `/api` routes (see SPA fallback).

Governor is NOT a global layer: `api_router.route_layer(GovernorLayer)` merged into the root router; `/health`, `/ready`, swagger/openapi, static/SPA live outside it and are never throttled. Governor: default **120 req/min per IP global** + **5 req/min per IP on auth login/register**, config-driven (see Config). Rationale (2026-10-11 amendment): Nest global 10/min was never enforced (no `APP_GUARD`) — mirroring it would 429 frontend bursts + shared-NAT users. Key extractor = peer `ConnectInfo` by default; `X-Forwarded-For` honored ONLY when peer is in `TRUSTED_PROXIES` (default empty = never trust; compose sets it only if a proxy is added). 429s render via the shared `problem_response` constructor (same problem+json + `Retry-After` as AppError). Per-process memory: correct for single `:3001`; N× limit with 2+ replicas — Redis-backed governor is the scale-out prerequisite.

## CORS (restrictive, dev-only open)

* `CorsLayer`: **explicit allowlist, no `Any`**. Dev default origin `http://localhost:5173` only (config-driven for prod); `allow_credentials(true)`; allowed methods `GET,POST,PUT,PATCH,DELETE,OPTIONS` — **`PUT` was added 2026-10-22**: `PUT /api/v1/cards/{id}/labels/{label_id}` is a served route and `PUT` is not a CORS-safelisted method, so omitting it made the browser's preflight fail and the request was blocked (every other verb worked — a maximally confusing partial failure). The method list stays hand-written (axum does not expose the route table), so it is guarded by a **preflight test** that asserts every served verb survives a CORS preflight; allowed headers `content-type,x-request-id` (auth is cookie-only — no `Authorization` header exists; do not allowlist it). Expose `x-request-id`.
* **Forbid `Any` + `credentials(true)` combination** (browsers reject it; fail boot if configured). Prod origins come from settings; empty prod allowlist = deny-all (fail closed). **The app-level boot check is load-bearing, not redundant** (verified 2026-10-22): `tower-http` 0.6.11's own `ensure_usable_cors_rules` runs inside `poll_ready`, so its guard is a **panic on the first request**, not a boot error — a misconfigured CORS layer would take the service down at runtime instead of refusing to start.
* **CSRF defence-in-depth: the Go 1.25 cross-origin algorithm (2026-10-22).** The API authenticates with an ambient cookie (`credentials: 'include'`). `SameSite=Lax` already blocks the cookie on cross-site `POST`/`PUT`/`PATCH`/`DELETE`, but that is a **browser** control: it does nothing for a non-browser client and nothing at all if a deployment ever relaxes `SameSite` to `None`. So a server-side check is required. **Decision: adopt `tower-http` 0.7's `CsrfLayer`** (feature `csrf`), which implements the Go 1.25 `net/http.CrossOriginProtection` algorithm step for step: safe methods (`GET`/`HEAD`/`OPTIONS`) always allowed; `Sec-Fetch-Site: same-origin`/`none` allowed; `Sec-Fetch-Site: cross-site`/`same-site` allowed **only** if the `Origin` is in the trusted set; with no `Sec-Fetch-Site`, a missing `Origin` means allowed (curl / server-side proxy / native client — no ambient cookie to abuse) and an `Origin` whose authority equals the request's effective host means allowed; otherwise **`403`** through the shared `problem_response` renderer and the **existing** `AppError::Forbidden` mapping (**no new problem-type URI** — the change is contract-neutral).
  **Why the algorithm and not the simpler "an `Origin` that is present must be in the allowlist" rule this section originally specified (corrected 2026-10-22):** browsers send `Origin` on **every** mutating request, same-origin included, and this service serves the SPA itself — so under the simple rule an operator who omits `CORS_ORIGINS` in production gets **every write 403'd**, with a CORS-shaped error that points nowhere near the cause. The algorithm's `Origin`/`Host` fallback removes that cliff: a same-origin SPA works with an **empty** allowlist. It also rejects the **`same-site`** case (a sibling subdomain), which `SameSite=Lax` *permits*.
  **The allowlist is canonicalized at boot, and one canonical list feeds three consumers.** `CsrfLayer` matches origins **byte-for-byte** and its own docs warn that a non-canonical entry *"will silently never match"*. So each `CORS_ORIGINS` entry is parsed to canonical form — lowercase scheme and host, the scheme's default port stripped, no trailing slash, no path/query/fragment, no opaque (`null`) origin — and a **non-canonical entry is a boot error naming the offending entry**. The canonical list then drives `CorsLayer::allow_origin`, `CsrfLayer::add_trusted_origin`, and the CSP's `connect-src`.
  **The compose dev topology is `same-site`, not same-origin** (`localhost:5173` -> `localhost:3001` is a different port), so it is allowed only because `http://localhost:5173` is in the default allowlist — an explicit AC, or dev breaks in a way that looks like a CORS bug.
  **Deployment caveat:** the `Origin`/`Host` fallback degrades if a reverse proxy rewrites `Host` (tower-http's own note); the runbook must require `Host` to be forwarded unchanged. `Sec-Fetch-Site` is only sent to *trustworthy* origins (HTTPS or localhost) — production is HTTPS; the plain-HTTP staging box falls through to the `Origin`/`Host` step, which works.

## Graceful shutdown

`main.rs`: `tokio::signal` listening for **both `SIGINT` (Ctrl-C) and `SIGTERM`** (docker/compose stop) → `axum::serve(listener, app).with_graceful_shutdown(shutdown_future)` → after HTTP drain, `pool.close().await` so idle MySQL connections terminate cleanly. Log shutdown start/finish with the instance ID. **2026-10-22:** the pool close is **bounded** by a timeout (default 10 s, `SHUTDOWN_TIMEOUT_SECS`) — an unbounded `pool.close().await` can hang on a wedged connection and the container then hits the orchestrator's kill timeout, turning a graceful stop into a SIGKILL.

## Observability

* **Structured logs.** `tracing-subscriber` gains the `json` feature; the formatter is selected by `APP_ENV` — **JSON** in production (what a log aggregator wants), human-readable `fmt` in development/test. `RUST_LOG` / `EnvFilter` behaviour is unchanged.
* **`/metrics` endpoint (Prometheus text format).** Served on a **separate listener** (see the exposure rule below), never throttled, never auth-gated like a domain route, and **never** rewritten by the SPA fallback. Series:
  * `kanpad_http_requests_total{method,route,status}` + `kanpad_http_request_duration_seconds` (histogram),
  * `kanpad_http_in_flight` (gauge),
  * `kanpad_db_pool_size` ← `sqlx::Pool::size()`,
  * `kanpad_db_pool_idle` ← `sqlx::Pool::num_idle()`,
  * `kanpad_db_pool_acquire_duration_seconds` ← **self-instrumented** (a small `acquire_timed()` helper that times `pool.acquire()`); pair it with `PoolOptions::acquire_time_level(LevelFilter::INFO)` so a slow acquire is also a tracing event,
  * `kanpad_throttle_rejections_total` (governor 429s),
  * process metrics (RSS, threads, uptime).
  **Correction (2026-10-22):** sqlx 0.8.6 has **no `PoolMetrics` type and no `metrics` feature** (verified against the vendored `sqlx-core-0.8.6` — its features are `_rt-*`, `_tls-*`, `any`, `default`, `json`, `migrate`, `offline`), and sqlx 0.9's feature set and changelog add no metrics support either — so this holds on **both** target versions. The pool gauges come from `Pool::size()` / `Pool::num_idle()`; the acquire-duration series is **our own** code.
* **Exposure rule (load-bearing):** `/metrics` must **not** be on the public API port — a public metrics endpoint publishes request rates, error rates and pool saturation to anyone. axum's own Prometheus example starts a **second server on a different port** for exactly this reason (*"The `/metrics` endpoint should not be publicly available"*), and `metrics-exporter-prometheus` ships an `http-listener` feature for it. Serve it on a **separate listener**, enabled by an optional `METRICS_PORT` key: **unset = no metrics endpoint at all** (fail-closed opt-in), set = a dedicated port.
* **No scrape feedback loop:** a `/metrics` scrape must not record itself (otherwise every scrape adds a request to the counter it is reading). Both `axum-metrics` and `docspec-http` guard this explicitly; do the same.
* **Cardinality rule (load-bearing):** the `route` label is the **matched route pattern** (`/api/v1/cards/{id}`), never the raw request path. A raw path makes every card id a distinct time series — a metrics-cardinality incident (and a cost) waiting to happen. The pattern comes from axum's `MatchedPath` extension — which requires the **`matched-path` feature** on `axum` — not from string surgery on the URI. Unmatched requests (404/405) use the literal `"unknown"`, never the raw URI (a hostile client could otherwise spam the label space).
* **Dependency note:** this adds the `metrics` + `metrics-exporter-prometheus` crates (the latter is the crate the `metrics` project's own README recommends for a scrape endpoint; the similarly-named `metrics-prometheus` is a different crate that pulls in the whole `prometheus` crate). Justification: the service already runs a rate limiter, a DB pool, a session sweeper and a governor and currently exposes **no** signal for request rate, error rate, pool saturation or 429 count — there is nothing to alert on.
* **`x-request-id` correlation** already spans logs and the problem+json `instance`; the metrics exporter stamps the same id on error-path exemplars where possible.

## SPA fallback + health

* **SPA fallback:** `ServeDir::new("public/")` for the built frontend (`public/` is populated from the frontend `dist/` build at image build time — see T06 Dockerfile; dev serves the frontend separately via Vite) + a fallback service: requests under `/api/*` that miss → JSON 404 problem (never `index.html`); `/swagger-ui*` and `/api-docs/*` excluded (never rewritten); everything else → `public/index.html`. Order: `/api` routes → swagger/openapi → static → fallback. Owned by T05 (with a fallback-order test).
* **Health (outside governor, no auth):** `GET /health` = **liveness, stable shape `{status:"ok"}`**, no DB touch (safe for orchestrator probes). `GET /ready` = readiness: `SELECT 1` via pool → `200 {status:"ok",db:"up"}` or `503` problem when MySQL is down. Both live outside `/api/*` so governor scope never touches them.

* `///` docs on every exported store fn + safety-critical SQL (lock order, ownership WHERE); no redundant narration. ## ADRs (short)

* Axum over Loco/Actix/Rocket/Poem: standard hiring/docs, Tower transfers, no dead-weight mailers/jobs; Loco would force SeaORM + generated layout.
* sqlx over SeaORM/Diesel: team SQL-fluent, explicit queries, no compile-DB for Diesel DSL debt; SeaORM's 10–20% convenience not worth new ORM; `diesel-async+deadpool` most setup. **2026-10-22: the sqlx 0.8-vs-0.9 question is CLOSED — 0.9.** 0.8 was pinned only because `tower-sessions-sqlx-store 0.15` required `sqlx ^0.8`; T65 replaces the store, so 0.9 is taken (with the collation pinned in `DATABASE_URL` so the driver version cannot change the session semantics).
* tower-sessions over JWT Bearer: preserves `credentials:include` frontend transport (no token-storage rewrite); force re-login covers rotation.
* tower-governor over hand-rolled/Fastify-Throttler replacement: per-IP + per-route layers, trusted-proxy-gated `X-Forwarded-For` (default peer IP only); auth 5/min hardens brute force, global 120/min is an abuse ceiling only (Nest's global 10/min was configured but never enforced — mirroring it would break frontend bursts and shared-NAT users; see Middleware order).
* Argon2id (new) + bcrypt (legacy-verify + upgrade) over bcrypt-12-everywhere: OWASP 2024–2026 primary is Argon2id; bcrypt stays only to verify pre-cutover cost-10 hashes without forcing password resets.
* `dotenvy + envy` over the `config` crate: ~10 keys don't justify ~30 transitive deps; same precedence, fail-fast `Settings::load()`.
* openapi-typescript (types-only) over orval/hey-api: keep hand fetch+React Query hooks, zero runtime, `erasableSyntaxOnly`-safe (see `40-typegen.md`).
