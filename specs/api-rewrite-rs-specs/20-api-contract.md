# 20 — API contract (new, not Nest-clone)

Parity waived. This file is normative for utoipa annotations alongside `21-api-standard-shapes.md` (21 holds the Nest→rewrite endpoint map; both files agree — if they ever disagree, fix the disagreement, neither silently wins). CI fails on drift (`openapi.json` diff).

## Transport (keep + fix)

* Base `/api/v1/*` (see Versioning below). Verbs are plural-noun REST (`GET` collection / `POST` collection / `GET|PATCH|DELETE` item). `GET /health` + `GET /ready` live outside versioning/governor (see below).
* Versioning: routers are mounted at `/api/v1/*`; the pre-version `/api/*` paths stay as a deprecated alias for one release (dual-mount, same handlers — NOT redirects, so method + body survive untouched), then removed. No unversioned new routes. openapi `servers` lists the `/api/v1` base.
* Cookie session (`connect.sid` in dev/test, `__Host-connect.sid` in prod; `credentials:include`), `snake_case` keys everywhere (`board_count`, `tag_ids`, `{label_id}`, `{target_column_id}`, `?project_id=` — see `21-api-standard-shapes.md`), int IDs as newtype `Path<BoardId>` etc. (`ToSchema(value_type = i32)`; Axum's default path rejection is already **400** but plain-text — map `PathRejection` **and** `QueryRejection` into problem+json 400; do NOT rely on the rejection's default body).
* **Request validation (Rust implementation, no Nest pipes):** garde `Validate` on every input DTO via `axum-valid` `Valid(Json<T>)` / `Valid(Query<T>)`. **All validation failures → 400** problem+json with an `errors[]` field→message map. Parity note (verified 2026-10-11): Nest has no global pipe, but per-endpoint `@UsePipes(new ValidationPipe({transform:true}))` on ~20 POST/PATCH handlers (NOT on `POST /api/auth/register|login`) means validation failures are 400 today for those mutations — status parity there; the `errors[]` map is a new (additive) shape. garde also covers auth inputs + GET query DTOs, which Nest mostly left unvalidated — new strictness, audited in T41* (pre-sanitize garbage query params or accept the 400 as a surfaced bug).
* `problem+json` rendering: global `AppError: IntoResponse` renders every error as RFC9457 `application/problem+json {type,title,status,detail,instance,errors?}` where `type` is a stable per-error URI (e.g. `https://kanpad.dev/problems/validation-error`, never `about:blank`) and `instance` is always set (`"{METHOD} {path}#{x-request-id}"`). Status mapping: validation/parse→**400** with `errors[]`, business `BadRequest`→400, 401/403/404/409 pass through, 429→problem+json + `Retry-After`, 503 pool-acquire, **503** origin-timeout (`HandleErrorLayer` + `Retry-After`; 504 is proxy semantics). Never 500 for validation/authz input errors.
* `message?` envelope field is dropped explicitly everywhere: no `{data,message}` or `{message}` bodies. Success bodies are typed (`201 {data}+Location`, `200 {data}` or `200 Page<T>`, or empty `204`). Frontend must not read `message`.
* Status codes: `201` + `Location` create, `200` read/update, `204` (no body) all deletes. No `200`-typed deletes anywhere.

## Errors (breakage adopted, also in CONTRACT-CHANGES.md)

* Nest `{statusCode,message[]|string,error}` → RFC9457 `application/problem+json {type,title,status,detail,instance,errors?}` with stable `type` URIs and always-set `instance`. Example: `400 {"type":"https://kanpad.dev/problems/validation-error","title":"Validation Failed","status":400,"detail":"title: length …","instance":"PATCH /api/v1/cards/7#…","errors":[{"field":"title","message":"length: must be at most 255"}]}`. Frontend dual-parses during migration (see `40-typegen.md`); `status` preserved on thrown `ApiError` (current frontend discards it).
* Throttle 429 is problem+json + `Retry-After` (Tower governor response mapped through the same renderer).

## Pagination (shared Page<T>)

* Shared `Page<T> = {data:T[],page:number,limit:number,total:number}` (serde struct + utoipa schema, `compose_name` e.g. `Page_BoardResponse`, explicit `T: ToSchema` bound). Shared `PaginationParams {page=1, limit=50}` is a custom extractor with manual strict checks (`page ≥ 1`, `1 ≤ limit ≤ 100`, integers) returning 400 + `errors[]` (same shape, not a garde derive — ranges live here, not in the garde catalogue).
* Clamp-vs-strict decision (documented choice): **strict 400, no silent clamp.** Out-of-range `page/limit` (0, negative, >100, non-integer) → **400** problem+json with `errors[]` (same class + status as every other validation failure — see Transport). Rationale: silent clamping hides client bugs and diverges between endpoints. Concretely retires the current notes-service `Math.min(query.limit ?? 50, 100)` clamp — replace with validated `PaginationParams` so `?limit=500` is 400, not a quiet 100.
* Top-level lists all return `Page<T>` via count query (never `data.length`): `GET /api/v1/projects`, `GET /api/v1/boards`, `GET /api/v1/columns/:col/cards` (`Page<CardSummary>`), `GET /api/v1/labels`, `GET /api/v1/notes`, `GET /api/v1/tags`. Old `{data,total=data.length}` (projects/boards) and bare `{data:T[]}` (columns/cards/labels/notes/tags) retired. No `GET /api/v1/boards/archived` duplicate — use `?archived=true`.
* Nested routes stay unpaginated, ordered `position ASC`: `GET /api/v1/boards/:id → {…board,columns[]}` (board+columns, NO cards — cards enter only via the columns list which embeds summaries) and `GET /api/v1/boards/:boardId/columns` (embeds cards; board-size N; paginating them would break board rendering). Column order `position ASC` is hardening (Nest `boards.service` loads `columns` relation with no ORDER BY) — record in `CONTRACT-CHANGES.md`.
* Notes list excludes `content` TEXT: list uses a `NoteSummary` select without `content` (detail `GET /:id` only). Same rule as cards list (never select card `description` TEXT in list; `has_description` boolean + `checklist_progress` via batch aggregation only).
* Frontend fix: `NoteFilters` (currently `{search?,type?,tagId?}` in `features/notes/notes.api.ts`) needs `board_id?:number; page?:number; limit?:number`, and list fetchers must send `?page&limit` and read the `Page<T>` envelope.

## Auth (force re-login)

* `POST /api/v1/auth/register{email,password}→201 {data:{id,email,role}} + Set-Cookie + Location: /api/v1/auth/me`, no `message` (current `{data,message:"Registration successful"}` drops `message`). `REGISTRATION_ENABLED=false→403`, dup→409. Passwords hashed Argon2id (see `10-architecture.md` AuthN/Z; bcrypt only verifies pre-cutover hashes with same-request upgrade; hash BEFORE `tx.begin()`, tx holds only `INSERT user + single multi-row INSERT labels`). User-create + 6-label seed wrapped in **one transaction** via `common::label_seed::ensure_default_labels` (`INSERT ... ON DUPLICATE KEY UPDATE` / `IGNORE`) (current `auth.service.register` saves the user then calls `seedDefaultLabels` sequentially — a seed failure leaves a user with no labels; move both into a single transaction). `session.cycle_id()` on register too.
* `POST /api/v1/auth/login→200 {data:{id,email,role}}`, no `message` (drop `"Login successful"`). Throttle 5/min, bad→401 same shape, no user-enumeration delta (dummy Argon2 verify against a static PHC at current params on unknown email; bcrypt-path timing delta accepted one-release). `session.cycle_id()` on login (fixation test: pre-login cookie ≠ post-login cookie).
* `POST /api/v1/auth/logout→204` (destroy + clear cookie). **Unthrottle logout**: remove the current `@Throttle(5/min)` on logout — logging out must never 429.
* **Throttling (Rust, 2026-10-11 re-scoped):** tower-governor on `/api/*` only — 120 req/min per IP global + 5/min on `POST /api/v1/auth/register|login`, config-driven (`THROTTLE_*` env). The old Nest global 10/min was configured but never enforced (no `APP_GUARD`) — blind mirroring would 429 frontend page-load bursts and shared-NAT users; documented in `CONTRACT-CHANGES.md`. 429 renders as problem+json + `Retry-After`. Logout stays unthrottled. `/health` + `/ready` live outside `/api/*` and are never throttled.
* `GET /api/v1/auth/me→200 {data:{id,email,role}}` else 401. Single guard rule: `AuthSession` requires `user_id (>0) + email + role` everywhere (unifies `SessionGuard`'s userId-only check and `me`'s triple check; session payload trusted except `GET /api/v1/auth/me` + admin routes MUST re-lookup the row — deleted → 401, demoted → 403 — per `10-architecture.md`). Post-cutover every old `connect.sid` → 401 `{"title":"Unauthorized"}` → frontend redirects to login (no silent refresh).

## Endpoints (condensed; full schemas live in utoipa DTOs; `21-api-standard-shapes.md` holds the Nest→rewrite map)

All paths below are `/api/v1/…` (deprecated `/api/…` alias mounted for one release). All deletes are `204` (no body). All keys/queries are `snake_case`.

* `projects`: `GET /api/v1/projects?page&limit&q&sort&order → Page<Project>` (`board_count` computed for real via a SINGLE aggregation (`LEFT JOIN boards ... GROUP BY p.id`; count query reuses the same WHERE without the join — never N+1 per-project queries) — old stub `0` in `projects.controller` dropped); `POST {name}→201+Location`; `PATCH /:id{name}→200` — missing/empty name→**400 with `errors[]`** (current service-level `BadRequestException('At least one field…')` 400 retired; `UpdateProjectDto.name` required non-empty so the DTO emits 400 with the field map); `DELETE /:id→204` (cascade boards).
* `boards`: `GET /api/v1/boards?project_id&archived&sort&order&page&limit → Page<Board>` (`project_id` int-parsed — invalid `?project_id=abc`→**400** problem; current manual `parseInt` yields `NaN` and silently ignores the filter); `archived=true` includes archived else hides (no `GET /archived` duplicate); `POST {name(non-empty after trim →400 with `errors[]` if blank; Nest `create-board.dto` lacks `IsNotEmpty` so `""` creates today — new strictness),background_color(hex),project_id?}→201+Location` — `project_id` int-validated (+ null allowed) and an ownership check (foreign project id → **404**, no oracle; currently unchecked on create), board + 3 default columns (`To Do/In Progress/Done` 0/1/2) created in **one tx** (current two-step save is non-atomic); `GET /:id→{…board,columns[]}` unpaginated; `PATCH {name?,background_color?,project_id?|null,view_mode?board|list,is_archived?}→200` (foreign project id → 404; archive/restore are `is_archived` flips, idempotent — verb routes `/:id/archive|/restore` deleted); `DELETE /:id→204` (hard). No `DELETE /:id/permanent`: deleting an **active** board → **409** state conflict; delete archived boards directly (see `21`).
* `columns`: `GET|POST /api/v1/boards/:boardId/columns` (nested list unpaginated `position ASC`, embeds cards; create `MAX(position)+1` via `SELECT COALESCE(MAX(position),-1) ... FOR UPDATE` in tx (unlocked MAX races duplicate positions), default `New Column`); `PATCH /api/v1/columns/:id{name}→200` (blank name →400 with `errors[]`; `""` maps to default only where specified, `"   "` rejected); `DELETE /api/v1/columns/:id→204` (cascades cards **and closes the position gap in the same tx** — current `remove` is a bare `remove(column)` with no gap-close and no tx); `PATCH /:id{sort_order:asc|desc}→200` (rewrite positions by `created_at`; verb path `/:id/sort` deleted); `POST /:id/move-cards{target_column_id}→200 {moved_count}` (same-board else 400, same-id 400, empty source → `200 {moved_count:0}` not an error, append at `MAX+1` in tx with source select `ORDER BY position ASC` (Nest `columns.service:191-193` loads source with no ORDER BY — target order must mirror source order); gap-close/open + point update are set-based range `UPDATE`s (never full-column reload+save loop), `SELECT ... FOR UPDATE` in ascending `column_id` order; verb path `/:id/move-all` deleted).
* `cards`: `GET /api/v1/columns/:col/cards?page&limit → Page<CardSummary{…,has_description,checklist_progress?}>` (never select TEXT in list); `POST /api/v1/cards{title(non-empty after trim),column_id,position?,description?(≤10k chars),due_date?(ISO-8601 valid-date-or-null)}→201+Location` — create with explicit `position` = insert-with-open-gap (single range shift + insert; never verbatim write that duplicates), `MAX+1` default via `FOR UPDATE`; `DELETE /:id` closes the gap in the same tx; `PATCH /:id→200` — scalar + move/reorder with **set-based range `UPDATE`s + `SELECT … FOR UPDATE` in a short tx** (same-column = one range shift + one point update; cross-column = close-gap + open-gap + point update; stable `(column_id,position)` lock order, `min(column)` first). Clamp-then-write: out-of-range positions are clamped and the **clamped** value is written (current code shifts neighbours clamped but writes raw `dto.position`); **cross-column move without explicit position appends at `max+1`**; pure helper `clamp_position(requested, len)` is the unit subject; `GET /:id→CardDetail{checklists{items},labels}` (`checklist_progress{completed,total,percent}` only if any checklist); `PUT /:id/labels/:label_id→200 {data:Card}` idempotent (keep `POST /:id/labels` alias one release, deprecated — alias body is `{label_id:number}` snake_case; legacy `{labelId}` also accepted during the release, then removed) — **frontend fix: `assignLabelToCard` return type `ApiResponse<{message:string}>` → `ApiResponse<Card>`** (backend returns `{data:CardResponse}`); `DELETE /:id/labels/:label_id→204` (404 if unassigned); `DELETE /:id→204`.
* `labels`: `GET → Page<Label>` (lazy-seed defaults if empty); `POST {name(1..50,trim,per-user unique→409),color:red|orange|yellow|green|blue|purple}→201+Location`; `PATCH →200`; `DELETE→204`. Whitespace-only names→**400 with `errors[]`** via DTO (string + min-length 1 after `trim`, not-empty) — same status as the current service-level `BadRequestException`, new `errors[]` shape; keep 409 per-user unique on create+update. Case-collision note: `utf8mb4_unicode_ci` makes `UQ_labels_user_name` case-insensitive (`'Work'` vs `'work'` collide → 409); assert in tests.
* `checklists`: `POST /api/v1/cards/:cardId/checklists{title}→201+Location`; `GET /api/v1/cards/:cardId/checklists→200 {data[]}` (small-N, unpaginated — added route); `GET /api/v1/checklists/:id→200`; `PATCH{title}→200`; `DELETE→204`; `POST /:id/items{text,position?}→201+Location` (`MAX+1` default; `position` int-validated `≥ 0` — **negative positions rejected 400 with `errors[]`**; current `CreateChecklistItemDto.position` is bare `@IsNumber()` accepting negatives/floats); `PATCH /api/v1/checklist-items/:itemId{text?,is_completed?}→200`; `DELETE→204` (stem locked to `checklist-items`; no parallel nested alternative shipped).
* `notes`: `GET /?search?&type=general|board|project|card&tag_id?&board_id?&page&limit → Page<NoteSummary>` (no `content` in list SELECT; **`type` is derived from which FK is set — there is no column**: `board` ⇔ `board_id IS NOT NULL` etc.; POST enforces at most one FK set (multiple →400; none = `general`); detail `GET /:id` must explicitly select `content` since it is `select:false` in the source entity; `LIKE %search%` on title with `%`/`_`/`\\` escaping, pattern built in Rust + `push_bind` only (never `push` of user input), `ORDER updated_at DESC`; `page/limit/tag_id/board_id` all int-validated with page/limit ranges — current `ListNotesDto` uses bare `@IsNumber()` with no int/range checks; no `GET /boards/:boardId/notes` duplicate — use `?board_id=`; list uses two-step IDs-then-enrich + `COUNT(DISTINCT n.id)` with the same WHERE builder for count and page — never `COUNT(*)` over the tags join); `POST {title,content(≤65535 chars — units are characters, both DTOs already 65535, keep + document),board_id?|project_id?|card_id?,tag_ids?}→201+Location` — **unknown tag_ids→404** (align create with update: current create silently drops missing tags while update throws `NotFoundException('Some tags not found')`; create must do the same length check); `GET /:id→200` (explicit `content` select); `PATCH→200`; `DELETE→204`.
* `tags`: `GET → Page<Tag>`; `POST {name(per-user unique→409, trim, not-empty),color?(default teal, free-form ≤20)}→201+Location`; `PATCH →200` — update gets **409 + trim + not-empty** (current `TagsService.update` has no uniqueness check, no trim, and `UpdateTagDto.name` lacks not-empty; add trim, empty→**400 with `errors[]`**, dup-name→409 like create); `DELETE →204`. `tag_ids` dedup + ownership check on notes link. **Frontend fix: tag `color` optional** (`CreateTagData/UpdateTagData.color: string` → `color?: string`; server defaults to teal). Same case-collision note as labels (`UQ_tags_user_name`).

## Validation catalogue (garde derives via `axum-valid`; all failures → **400** problem+json with `errors[]`)

`email` (garde email validator — approximate mapping of validator.js `isEmail`; borderline addresses may differ, note in `CONTRACT-CHANGES.md`), `password-strength ≥8 + digit/symbol` **register/create-admin only** + `password byte cap ≤72` on all password inputs + `login password = non-empty + byte cap only` (never bare garde `length` — see `10-architecture.md` Validation), `name/title/text` lengths above, `hex_color`, `label_color enum(6)`, `view_mode enum(board,list)`, `sort_order enum(asc,desc)`, `note type enum(general,board,project,card)`, `due_date` ISO-8601 valid-date-or-null (JS `new Date()` parse differs — pin ISO-8601, note delta in `CONTRACT-CHANGES.md`), `project_id` int (boards create/update, nullable on update), `target_column_id ≥ 1`, `tag_id/board_id` int (notes list), `checklist-item position` int ≥ 0 (negatives/floats →400), not-empty (after `trim()` + min length 1, so whitespace-only →400 with `errors[]`) on board-create name / board-update name / project-create+update name / column name / tag-create+update name / label-create+update name / checklist-item text, per-user uniqueness →**409** (label name, tag name — case-insensitive under `utf8mb4_unicode_ci`, see `30-db-schema.md`). `page/limit` ranges live in the custom `PaginationParams` extractor (same 400+`errors[]` shape, not garde). Uniqueness stays 409, role-denial stays 403, state conflicts stay 409, not-found/foreign stays 404 (detached-label delete is 404, not 409) — never 400-by-accident, never 500.

## Nullability (wire)

| Field | Shape | Rule |
|---|---|---|
| `description` (card detail), `content` (note detail) | `Option<String>` emit-null | `null` emitted when absent (mirrors Nest null-vs-omitted) |
| `checklist_progress`, `has_description` (list summaries) | `Option<T>` + `skip_serializing_if` | absent when empty/false-equivalent; list summaries never carry TEXT |
| all other `Option` DTO fields | per-task table in T08 | each resource task states emit-null vs skip; do not re-decide per endpoint |
