### Rust backend (`backend-rs`)

- The session store follows the POOL's database: `AppState::with_pool(settings, pool)` binds `MySqlStore` to `pool.connect_options().get_database()` (`.with_table_name("sessions")`). `#[sqlx::test]` builds its pool with `.database(&db_name)`, so the per-test DB name is already in the connect options — no `SELECT DATABASE()` round-trip and no hand-wired store in tests. Production boots through `AppState::from_settings`.
- `MySqlStore::with_schema_name` validates identifiers STRICTER than MySQL (rejects a leading digit, `-`, `.`, space). `Settings::validate` screens the DB name via `db::is_valid_db_name` so a bad `DB_NAME` is a clean `ConfigError` — never a boot panic when the store is constructed. `DATABASE_URL` and `DB_NAME` are two spellings of the same value; validate whichever is in play.
- `dotenvy::dotenv()` never OVERRIDES an existing env var — it only ADDS missing ones. So a developer's local `.env` silently re-supplies a key a test deliberately unset, and a "this must fail to boot" assertion passes for the wrong reason. `Settings::load_from_env()` (no dotenv) exists for exactly this; the config unit tests use it, boot uses `Settings::load()`.
- Rust test helpers: in-process suites own their plumbing in `backend-rs/tests/api/helpers.rs`; black-box (raw TCP) suites share `backend-rs/tests/api/wire.rs`. Import EXPLICITLY (`use super::helpers::{…}`) — a glob import lets a leftover local copy silently win, while an explicit import is a hard `E0255`. That compile error is the regression guard for "no per-suite helper copies".
- The two black-box suites and the in-process suites assert problem+json through ONE core (`helpers::assert_problem_fields`); the transport-specific `assert_problem` functions are thin adapters. Keep new problem assertions in the core.
- `backend-rs/tests/api.rs` needs an explicit `#[path = "api/<name>.rs"] mod <name>;` for every suite — a bare `mod health;` resolves to `tests/health.rs`, which does not exist.
- `cargo fmt --check | tail` MASKS the exit code (the pipeline's status is `tail`'s). Capture `$?` without a pipe (`> file; echo $?`).
- A test that binds a FIXED port (e.g. `TcpListener::bind(":3001")`) breaks under cargo's parallel test scheduler when two suites in the same binary pick the same port — and also breaks if a dev server already holds that port. Bind port **0** (OS-assigned ephemeral) and drive `listener.local_addr()`; the OS may hand out a different port than requested, so never re-derive the address from the requested port. `wire::bind_blackbox()` in `backend-rs/tests/api/wire.rs` does this for both black-box suites; `E2E_BASE_URL` pins a fixed port when an operator needs one.
- A normative ownership header that the CODE VIOLATES is worse than no header — a future contributor trusts it and copies the pattern. The E0255 guard only fires for names a suite actually IMPORTS, so a suite can shadow a shared name forever just by not importing it (`auth_register.rs` aliased `json_of as parse_json` to dodge the collision; `throttle.rs` imported nothing from `super::helpers` at all and kept its own `send` + a duplicate `PROBLEMS` const). Audit the forbidden set against the actual `fn` definitions, not against the import statements — and when a suite legitimately needs its own helper, it must take a name OUTSIDE the forbidden set AND be listed in the header's "Sanctioned exceptions".
- When auditing a forbidden set, grep for the DEFINITIONS, not the imports — and make sure the pattern covers EVERY name in the set. A first audit of the session-store change missed `health.rs`/`errors.rs` shadowing `test_settings`/`test_app` and three suites duplicating the `PROBLEM_BASE` literal, purely because the grep pattern had omitted those names. Grep the whole forbidden set, then re-grep for the constant's VALUE (`https://kanpad.dev/problems`) to catch inline duplicates of a "constant" that were never imported.


### Fractional sort keys (2026-11-15, T010)
- **The DB unique index is the correctness backbone; the retry is the UX layer.** `UNIQUE(parent, sort_key)` turns same-gap concurrent inserts into a `1062`; the scoped matcher (`UQ_*_sort_key` only) retries 5× and surfaces a real conflict for anything else. Deterministic midpoint keys mean two same-gap inserts ALWAYS collide — without the retry that pair surfaces a 409 for one of them.
- **`ascii_bin` is load-bearing.** base62 keys sort correctly under binary byte order only; any `*_ci` collation reorders silently (mixed-case keys compare out of alphabet order). Pin it in the DDL AND in a collation test.
- **`@@transaction_isolation` reports the SESSION default, not the running transaction's level** (verified on MySQL 8.4 and MariaDB 11.4 — `SET TRANSACTION … READ COMMITTED` before `begin()` still reads `REPEATABLE-READ` inside the tx). Per-transaction isolation is only observable via `performance_schema.events_transactions_current` — which exists on MySQL 8.4 (`ISOLATION_LEVEL`) but NOT on MariaDB. Portable trigger-based isolation probes must branch per server; MySQL-only probe code silently proves the wrong thing on MariaDB.
- **`PS_CURRENT_THREAD_ID()` does not exist on MariaDB** (MySQL-only). A portable `ps_thread_id` probe substitutes `SELECT thread_id FROM performance_schema.threads WHERE processlist_id = CONNECTION_ID()`, or records a constant where no per-tx view exists. Test helpers that bypass the app (fault-injection SQL in test suites) still need both legs of verification.
- **Live-schema `query!` compilation and the `.sqlx/` cache must be migrated together.** After a migration that drops a column, `cargo check` against the live dev DB fails across the whole workspace until EVERY `query!` describing that column is gone — including in test fixtures, which `sqlx::test` compiles against the same cache. Fix the fixtures (seed via the new columns) as part of the migration, not "test cleanup".
- **The `.sqlx/` regenerate needs a database named `kanpad` with the migration applied** — a scratch DB with a different name yields a cache keyed to the wrong DB and `prepare --check` keeps passing against dead DBs (T009). Bind it with `cargo sqlx prepare --workspace --all -- --all-targets`, run `cargo sqlx prepare --check --workspace --all -- --locked --all-targets` after, and commit the result.
- **Two-phase rewrite for ANY bulk rekey into an overlapping key space.** Single-phase `UPDATE … CASE` assigning even keys collides with un-rewritten rows whose new key equals an old key (InnoDB checks the unique index per-row as the statement executes). `sort_order` rewrites collided immediately with seeded `a0..a2 → a0..a2` shuffles — every bulk rekey (sort_order, rebalance, move-cards append where the target may re-contain a parked key) must park at `tmp-<id>` (outside the base62 space) first, then assign.
- **Correlated `COUNT(*) … sort_key < ?` scalar subqueries in `query!` flip every outer column nullable in the server describe** — pin every column with `AS "col!"` or `AS "col!: Type"`, or the row type differs per server and the macro won't compile on one of them.

### Review-fix pass lessons (2026-11-15, T010 F1–F6)
- **Park exactly the row set you captured, never the parent.** A two-phase rekey that locks rows in phase 0 but re-filters by `parent = ?` in phase 1 lets a mid-rebalance INSERT (free to commit — its INSERT takes its own index-record locks) get parked at `tmp-<id>` and stranded past phase 2 (which only re-keys the captured ids) → non-base62 key → `key_between` bounds error 500 on the next move. Filter phase 1 by the SAME captured ids (`id IN (…)`, chunked), the pattern `rewrite_card_sort_keys` already used.
- **A retry matcher wired on one call site documents itself nowhere else.** T010's `1062`-on-`UQ_*_sort_key` retry existed only on the card create/move paths while specs claimed it generally — the two new reorder endpoints had none. When a handler computes between-neighbour keys with unlocked reads, it needs the same `MAX_ATTEMPTS` + `is_transient_lock_error` loop (rollback before retry, READ COMMITTED, linear backoff) — otherwise a same-midpoint race is a user-facing 500. One-shot BEFORE UPDATE/INSERT triggers with `SIGNAL … MYSQL_ERRNO=1062, MESSAGE_TEXT='…for key ''UQ_*_sort_key'''` (scoped — the matcher parses that suffix) prove each path retries to 200/201 with the flag consumed; MyISAM flag tables survive the rollback by design.
- **A post-mortem "fix it everywhere" must be enforced by a grep, not by memory.** The same matcher had to be applied to five call sites; `grep -rn "is_transient_lock_error\|MAX_ATTEMPTS"` is the audit that proves coverage.
- **Test-only cleanup after a panicking `.await` is unreachable.** Scratch-database drops placed after the test body never run on failure (panics unwind past them) — spawn the body and drop the scratch DB from the `JoinHandle` afterwards; the test still fails loudly with the body's panic message, now without littering dev databases.
- **Dead `query!` macros orphan their `.sqlx/query-*.json` cache files.** Deleting the function is only half of the job — `cargo sqlx prepare --check` fails on the stale cache; regenerate/delete the orphan in the same change (T009 rule).

### Spec-review pass lessons (2026-11-16, arch-hardening/MCP/security spec review)
- **A spec's "current state" claim is stale the moment a parallel task lands** — even the amendment whose job was to "re-verify against the tree" re-verified only half of it. Re-derivation must be a fresh, whole-tree `grep` (e.g. `is_transient_lock_error|MAX_ATTEMPTS` → 6 sites; `FOR UPDATE` → 32 sites / 7 files), not a spot check, and both the findings register AND the design file AND the pending task file must carry the correction — the stale claim survived in three places at once.
- **Transitive dependency reachability is not importability.** "rand arrives via rmcp" does not make `use rand::…` compile — declare direct deps explicitly (and re-derive `deny.toml` from a fresh `cargo deny check`, per its own header).
- **A designed-but-uncatalogued tool is a spec contradiction, not a gap.** The MCP `link_artifact` was referenced by six files (workflows, security, task map, frontend, README) but missing from the tool catalogue, the annotation→scope table, the persistence-test matrix — and its `card_links` DDL was allocated a migration number without any columns. Every cross-referenced tool/table/route needs its row in the one normative catalogue; then grep for the name to confirm zero orphans.
- **Candidate SQL in specs with an argument list still needs the same review as code.** The `INSERT … ON DUPLICATE KEY UPDATE` candidate referenced `note = VALUES(note)` with `note` absent from the INSERT column list — silently dropping the claim note and resolving `VALUES(note)` to NULL on re-claim. Prefer the obviously-correct construct (`SELECT … FOR UPDATE`) as the default; keep the exotic one as documented alternative only with full syntax + engine notes.
- **A one-call privilege escalation hides in the method map.** If the bearer REST scope map is `method → scope`, any `write` key can `POST /api-keys` and mint a wider key. Key-lifecycle routes need explicit cookie-only (or scope-capped) exclusions — the same treatment as `/auth/*`. Audit the exception list as part of the map, not as a footnote.
- **A security folder's out-of-date claim is a liability, a spec's is a stale fact.** Findings-register SLA/severity text must be corrected in place or explicitly marked superseded; leaving a wrong "SLA lapsed" note in place costs reviewer trust more than the underlying finding does.

### T020 — tx-retry helper for single-shot transactions (2026-11-18)
- **A stable closure retry kernel cannot borrow the connection.** `for<'c> FnMut(&'c mut MySqlConnection) -> ...` (or `AsyncFnMut` + a boxed `CallRefFuture` — also unstable to *name*) forces the body's future to be valid for **every** `'c`, so stack-borrowed captures (`input`, `&calls`) can never satisfy the bound. What works on stable: pool-owned transactions are `Transaction<'_, MySql>` whose lifetime is free — pass the **Transaction BY VALUE** into the body and **take it back** for commit/rollback; the body's future may borrow the stack freely. sqlx `PoolConnection` is `'static`-owned (reattach is Arc-based), so `Transaction::begin(MaybePoolConnection::PoolConnection(conn), None)` yields a `Transaction<'static, MySql>` whose own lifetime constrains nothing.
- **On the error path the body drops the Transaction — that IS the rollback between attempts.** sqlx's `Transaction::drop` calls `start_rollback`, queued *before* control reaches the retry decision; the next use of that connection executes ROLLBACK first (1213 has already unwound server-side; a 1205's half-applied tx is covered by the queued rollback). Explicit `rollback().await` is only possible on the paths that return the tx (`Done` → commit, `Restart` → rollback); treat the error path as drop-queued (assert it with an always-fire injector: fires == MAX_ATTEMPTS and the survivor row).
- **Backoff bounds and the sleep-holds-no-connection invariant are testable without a mocking framework.** `#[sqlx::test]` cannot set `max_connections`, so build a manual `MySqlPoolOptions::new().max_connections(1)` pool on `DATABASE_URL` (begin/rollback only — no tables touched; `DROP TABLE IF EXISTS`/`DROP TRIGGER IF EXISTS` at both ends since the CI DB is shared). A retry that slept while holding the pooled connection deadlocks the second attempt into a `PoolTimedOut` — the test fails loudly. Assert `fires == MAX_ATTEMPTS` (the MyISAM fault counter doubles as the attempt counter) and the survivor row to prove rollback-between-attempts end to end.
- **Boundary classification beats a new `AppError` variant.** 1213/1205 surfacing at the HTTP boundary map in the `Db` arm to 503 + `Retry-After: 2` (pool/Io errors already did; `RowNotFound`→404 and 1062→409 are the same pattern). The matcher stays in `common/retry.rs` (single home, never duplicated); the boundary downcasts the driver error with a documented `40001` SQLSTATE fallback (stub-constructible in unit tests), while `1205`/`HY000` needs the driver's `number()` — so `1205` is covered by the injector API tests, `40001` by pure boundary unit tests.
- **`1213` is SQLSTATE `40001` but `1205` is `HY000`** — never SQLSTATE-match a lock-class error; match the driver NUMBER.
- **The MyISAM fault-table injector IS the attempt counter.** `Counted(n)` gives recovery tests (fires exactly n then succeeds — the 204/201 write persists); `Always` gives exhaustion tests (fires == 5, 503 + `Retry-After: 2`, body carries no driver text). One trigger shape, both modes.
- **`CREATE/DROP TRIGGER` is not preparable** (MySQL 1295) — `raw_sql` sends COM_QUERY, `query()` goes through COM_STMT_PREPARE. `DROP TABLE IF EXISTS` via `query()` is fine.
- **`cargo fmt` is a parse check, not just a formatter** — it refused to write because of an unclosed delimiter (`|tx| { Box::pin(async {` factory with mismatched `})` closers from a mechanical edit), catching the breakage before `rustc`. If a scripted multi-file edit produces unbalanced parens, `cargo fmt` names the file.
- **Jitter without a dependency would have needed one anyway** — `rand 0.10` was already in the tree (transitively); declaring it direct is the cheapest AWS/SRE-jittered backoff (`rand(5, 20·retry)` ms) available. Verify license class against `deny.toml` before adding anything new.
