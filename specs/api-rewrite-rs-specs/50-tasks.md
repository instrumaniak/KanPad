# 50 — Step-by-step tasks (executor source of truth)

Rules: one task = one PR = one behavior (≤5 files, ≤1–2 endpoints; kernel tasks T04/T05/T11 exempt); TDD red→green (paste failing-test output before the fix or link the red CI run; no test deleted/skipped/weakened); DB re-read on every mutation; cite contract section (`20-api-contract.md` + `21-api-standard-shapes.md` — the two agree; if they disagree fix it, neither wins) + schema section (`30-db-schema.md`) where applicable; list `Touch only` (per-file for `src/common/*`); state `Depends/Blocks`; paste evidence. Global DoD in `00-overview.md` applies to all.

Global per-task evidence checklist (paste commands + outputs in every PR):

* `cargo fmt --check`
* `cargo clippy --workspace --all-targets -- -D warnings`
* `cargo test -p backend-rs --test api <filter>` (or `cargo test -p backend-rs` for kernel tasks) green
* `cargo sqlx prepare --check --workspace --all -- --all-targets` green (prepare flag form is fixed everywhere; T03 proves it runs)
* `.sqlx/` committed if any `query!`/`query_as!` changed (no `.sqlx/` change → state "no query change")
* Every 4xx/5xx asserts `Content-Type: application/problem+json` + exact `type` URI from the `10-architecture.md` registry
* Every POST/PATCH/DELETE asserts persistence via second GET or direct sqlx `SELECT`
* Injection regression per resource: quote payload stored literally, sort-allowlist violation → 400 problem+json
* Paste failing-test (red) output before the fix (or link the red CI run); state no test was deleted/skipped/weakened
* 403 vs 404 vs 409 rule: foreign/not-owned resource id → `404` (no oracle; detached-label delete is 404, not 409); authenticated-but-role-denied (`REGISTRATION_ENABLED=false`, non-admin on admin route) → `403`; wrong-state operations (deleting an active board) → `409`
