# 00 — Overview, scope, locked decisions

## Intent

Rewrite `KanPad/backend/` (NestJS 11, TypeORM 0.3, `mysql2`, Fastify + `@fastify/session` + `connect-typeorm`) as idiomatic Rust (`backend-rs/`). Nest is behavior reference only — not a template. Every API, schema, and pattern decision follows industry standards and Rust community best practices. All spec files agree with each other; the Amendments below are the decision log. Optimize for small-team maintainability, explicitness, and testability — not for response byte-parity.

## Facts about the source (verified read-only)

* `backend/src/app.module.ts:1` — 10 feature modules + global `ConfigModule` + `ThrottlerModule(10/min)`.
* `backend/src/main.ts:30` — Fastify + `fastifyCookie` + `fastifySession(TypeormStore, connect.sid, 24h)` + `helmet(csp:false)` + `compress` + Swagger `api/docs` + SPA fallback. No global `ValidationPipe`.
* Auth is **cookie session, not JWT**: `backend/src/auth/auth.controller.ts:1` (`register/login/logout/me` mutate `session{userId,email,role}`), `backend/src/auth/guards/session.guard.ts:1` gates all domain controllers. No `passport`/`jsonwebtoken` anywhere.
* DB is **MySQL** (`backend/src/database/data-source-options.ts:5` `type:'mysql'`), 10 TypeORM migrations in `backend/src/migrations/`, journal `typeorm_migrations`. Entities use `INT AUTO_INCREMENT` PKs, `DATETIME` timestamps, no UUID/JSONB/soft-delete (`is_archived` bool on boards instead).
* Envelopes: single `{data,message?}`, lists `{data,total=data.length}` (projects/boards only, no real pagination). Errors: Nest `{statusCode,message:string|string[],error}`. Frontend `frontend/src/features/*/*.api.ts` copy-pastes `handleResponse` + `FETCH_OPTIONS{credentials:include}` per file; centralized `@/lib/api` from AGENTS.md not implemented.
* No uploads, no websockets/queues, no `activities` entity (specs-roadmap only).

## Locked decisions (2026-10-10)

1. **sqlx-only 0.8, no SeaORM.** Team is SQL-fluent; wants minimal deps, explicit queries, fastest builds. Pinned to **0.8 until `tower-sessions-sqlx-store` supports 0.9** (in-repo `SessionStore` impl is the documented escape hatch). Relations/pagination hand-rolled via `query!`/`query_as!` + `QueryBuilder`. See `10-architecture.md`.
2. **Keep MySQL 8 (pin `8.4`).** No engine switch. Placeholders `?`, `NaiveDateTime↔DATETIME`, `last_insert_id()` for creates. Dev/test/prod same minor.
3. **Force re-login with a fresh session table.** Keep cookie-session mechanism (`tower-sessions 0.14` + `tower-sessions-sqlx-store 0.15`, `connect.sid` in dev/test + `__Host-` prefix in prod, sliding 24h TTL) but issue fresh sessions with a new `SESSION_SECRET` in a **new store-owned `sessions` table in the app database** (Nest's singular `session{id/json/expiredAt/destroyedAt}` table is not reused). Do NOT chase byte-compat with `@fastify/session` + `connect-typeorm` row codec. **(The `tower-sessions 0.14` + `tower-sessions-sqlx-store 0.15` pins are superseded by Amendment 12 — the store is now in-tree and `tower-sessions` is 0.15.)** Old sessions 401 → login screen. Passwords upgrade without resets (Argon2id new, bcrypt cost-10 verify + same-request rehash).
4. **Adopt `application/problem+json` (RFC9457) + real `?page&limit` pagination.** Declared breakage vs Nest envelope; documented in `20-api-contract.md` + `CONTRACT-CHANGES.md` (created in T01). Frontend migrates via centralized `apiFetch` + generated types (`40-typegen.md`).

## Amendments (2026-10-11 decision log — all folded into the base files on the 2026-10-11 cleanup; no "override" layers remain)

1. **Validation status is canonical 400** (with `errors[]` field→message extension) — NOT 422. Verified 2026-10-11: Nest has no global pipe, but per-endpoint `@UsePipes(new ValidationPipe({transform:true}))` exists on ~20 POST/PATCH handlers, so validation failures are **400 today for mutations except `POST /api/auth/register|login` (no pipes there — `RegisterDto`/`LoginDto` decorators are dead code, weak inputs reach the service today)**; 400 is parity for those mutations, **new strictness for auth register/login + GET query DTOs** (mostly unvalidated in Nest).
2. **Pagination is strict, no silent clamp**: out-of-range `page`/`limit` → **400** problem+json with `errors[]` (not clamped, not 422).
3. **Session store owns its own table** (2026-10-18 amendment): the baseline creates a store-owned `sessions` table **in the app database** (`.with_schema_name(<current DB>)` + `.with_table_name("sessions")`, fail-fast DDL) and ships the `tower-sessions-sqlx-store` DDL verbatim. Nest's singular `session` table is NOT renamed and NOT in the baseline — no collision (different name), abandoned at cutover. (Reverses the `session`→`sessions` rename plan.)
4. **Global throttle re-scoped**: governor covers `/api/*` only (`/health` + `/ready` live outside `/api`), limits config-driven — 120 req/min per IP global + 5/min on auth (Nest's global 10/min was never enforced; blind mirroring would break frontend bursts and shared-NAT users).
5. **`sqlx` pinned to 0.8 everywhere**: `tower-sessions-sqlx-store` 0.15.0 (latest) depends on `sqlx ^0.8` + `tower-sessions-core ^0.14`, which also pins `tower-sessions` to 0.14 (0.15 exists but is incompatible with the store). **SUPERSEDED by Amendment 12** — the store is now owned in-tree, so both pins are lifted.
6. **Canonical `sqlx prepare` form**: `cargo sqlx prepare --check --workspace --all -- --all-targets` everywhere (harmless no-op flags on a single crate; one form, no drift).
7. **Rewrite deltas (2026-10-11, folded into `10/20/50`):** 3-file feature layout (`routes/store/types`, `MySqlExecutor` generics, no repository traits), newtype IDs + `snake_case` wire names, set-based position `UPDATE`s with `SELECT ... FOR UPDATE`, ownership in SQL (`404` foreign, `403` role-only, `409` state conflicts), `HandleErrorLayer→503` + middleware order (`RequestId→Trace→Cors→Governor→Compression→Timeout→Session`), `thiserror`-only `AppError` + `axum-valid` + `secrecy` (byte-length checks), Argon2id with bcrypt upgrade path, `__Host-` cookies in prod, `[[test]] api` target, CLI `serve/migrate/create-admin/export-openapi` (`serve` never auto-migrates by default). Rationale record: `11-rewrite-deltas.md`.
8. **Live unicode + migration (2026-10-11, folded into `10/30/50`):** prod is MariaDB 10.6.28, all tables `latin1` via bare `ENGINE=InnoDB`, 1 non-ASCII char `’` so conversion is still lossless; `utf8mb4_unicode_ci` portability rule; `0002_convert_to_utf8mb4.sql` (`CONVERT TO`, `ROW_FORMAT=DYNAMIC`, emoji gate test, MariaDB-10.6 staging proof); cutover is blue-green ONLY (transformed restore with `--ignore-table` + ghost-column strip; no stamp; prod rollback = restore backup). Runbook: `31-live-unicode-migration.md §31.5`.
9. **API standard shapes (2026-10-11, folded into `20/50`):** `/api/v1` versioning (deprecated `/api` dual-mount one release), uniform `204` deletes, no verb URLs (`archive/restore/permanent/sort/move-all` replaced), no duplicate routes (`/boards/archived`, `/boards/:id/notes` deleted), full `snake_case`, added `GET cards/:id/checklists` + `PUT cards/:id/labels/:labelId`, `/health` + `/ready` outside `/api`. Map: `21-api-standard-shapes.md`.
10. **Rewrite framing (2026-10-11):** this plan is a **Rust rewrite, not a port**. Nest is behavior reference only. No NestJS-isms (DI-container layouts, repository traits, verb URLs, `message` envelopes, `latin1` defaults) are carried into `backend-rs/`.
11. **Rust-idiom naming + quality baseline (2026-10-22, folded into `10/50`):** the last two Nest/Node artifacts are dropped — `NODE_ENV` → **`APP_ENV`** (values unchanged `development|test|production`; boot **fails** when `NODE_ENV` is present, so a stale deployment can never silently downgrade to `development` and lose `Secure` cookies + `__Host-` + prod HSTS + deny-all CORS), and the session cookie `connect.sid` → **`kanpad.sid`** (`__Host-kanpad.sid` in production — the express-session default is not carried over; the `__Host-` invariant `Secure`+`Path=/`+no `Domain` becomes **test-locked**). The rewrite's CI workflow moved from `backend-rs/.github/workflows/` to the **repo root** `.github/workflows/` (`.github/workflows/backend-rs.yml`) — GitHub discovers workflows ONLY at the root, so the pipeline had **never run** and every gate in it (fmt, clippy, the `unwrap` grep gate, `prepare --check`, `cargo audit`/`deny`, the openapi diff, the docker build) was unverified; that also revealed the repo's own `unwrap`/`expect` grep gate failing on three sites, the `no format! in store.rs` gate failing on two false positives, and `allow_methods` missing `PUT`. **T54 + T55 landed the naming pair and the CI activation** (the `PUT` fix + the preflight guard included — a guard that lands red is not a guard). Quality-baseline fixes folded in: CORS `allow_methods` gains **`PUT`** (label-attach was blocked by the browser preflight), `#[tracing::instrument]` handlers **skip the request body + session** (the span recorded `email` and card `title`/`description`), an **`Origin` check** on mutating requests (CSRF defence-in-depth) + a **CSP** on the origin that now serves the SPA itself, **`/metrics`** + JSON production logs + pool metrics, `Role`/`AppEnv` **enums** replace `String`, shared-kernel DRY (`common::time` single owner; `common::ownership` implemented instead of stubbed), build chain (`[lints]` with `missing_docs = deny`, `[profile.release]`, `rust-toolchain.toml`, `deny.toml`, `license`, **edition 2024**), concurrency (deadlock/lock-wait retry, `READ COMMITTED` for the move tx, env-driven pool sizing), Docker (`.dockerignore`, `HEALTHCHECK`, digest pins), and a `cargo-llvm-cov` coverage floor. Detail + the ten-axis scorecard (every axis to ≥ 9.5/10) + the **verification pass** (every claim re-checked against primary sources on 2026-10-22; **14 details corrected**, 3 of them breaking — the CSP's `connect-src`/`script-src` and the isolation-level statement's position relative to `BEGIN`; the correction table is in `54-rust-idiom-hardening.md` §"Verification pass"): `54-rust-idiom-hardening.md`.
12. **Dependency hygiene + modernization (2026-10-22, folded into `10/50`; `54` Part C).** A second, deeper review of `backend-rs/Cargo.toml` found **three dead direct dependencies** — `axum-valid` (0 references, yet it dragged a **second, complete axum 0.7.9** into the tree, plus `validator` 0.18 via `axum-valid 0.20`'s default features, plus a second `garde` 0.20), `utoipa-axum`, `zeroize` — and **two dead `tower-http` features** (`timeout`, `limit`); `secrecy`'s `serde` feature is **load-bearing** and stays. The **session store is now owned in-tree** (`src/common/session_store.rs`, implementing `tower_sessions_core::SessionStore` over the app pool, keeping the existing `sessions` DDL and the **MessagePack** payload unchanged — a code-ownership change with no data implication), because `tower-sessions-sqlx-store 0.15` (last release **2025-01-01**; its dependabot bump to sqlx 0.9 **open since 2026-05-21**) requires `sqlx ^0.8.0` **and** `tower-sessions-core ^0.14.0`, which made **both** dependency majors unreachable (a second sqlx / a second `tower-sessions-core` = a compile error). That unlock allows: **`sqlx` 0.8 → 0.9** (the feature names change — `runtime-tokio-rustls` → `runtime-tokio` + `tls-rustls-ring-native-roots`; the `DATABASE_URL` now **must** carry `collation=utf8mb4_unicode_ci` so the driver version cannot change the session collation, and the pin must appear in **all five** places the URL lives); **`tower-sessions` 0.14 → 0.15** (the "Fix memory ordering race" release); **`tower-http` 0.6 → 0.7**, which brings the **`csrf`** feature — the **Go 1.25 `CrossOriginProtection` algorithm**, adopted for the mutating-request cross-origin check (it has the `Origin`/`Host` fallback the original hand-rolled rule lacked, so a same-origin SPA works with an **empty** origin allowlist instead of every write 403'ing; the allowlist is now **canonicalized at boot**, so a non-canonical entry is a boot error naming it rather than a silent non-match, and the rejection reuses the **existing** `AppError::Forbidden` problem type — **no new problem-type URI**, so the change is contract-neutral); **`utoipa` 5 → 6** + **`utoipa-swagger-ui` 9 → 10** (lockstep; the emitted OpenAPI changes, so `openapi.json` + `schema.d.ts` regenerate in the same PR); **`argon2` 0.5 → 0.6** + **`bcrypt` 0.17 → 0.19** (the same `password-hash` 0.6 wave — they move **together**); **`sha2` 0.10 → 0.11** (the lock already carried it transitively → this dedupes it); **`garde` 0.22 → 0.23**; **`dialoguer` 0.11 → 0.12**; and the **`tower_governor`** exact pin relaxed to `0.8`. The **toolchain moves 1.96.1 → 1.99.1** — the *current* stable (the first draft of the spec named the superseded `1.99.0`) — with the Dockerfile base moving to `rust:1.99-bookworm` **in the same PR** (the Dockerfile and the toolchain move together, never one alone); it clears the MSRV ceiling of the target dependency set (sqlx 0.9's `1.94.0` is the highest, everything else ≤ 1.88). **Why now:** the NestJS data has **not** been migrated yet — the toolchain pin gates `edition = "2024"` → `resolver = "3"` → the *entire* dependency set, and the driver major touches the DB connection semantics + the `.sqlx/` cache, so both are cheap now and expensive after the cutover. The `bcrypt` dependency gains a **measurable exit criterion** (`SELECT COUNT(*) FROM users WHERE password_hash NOT LIKE '$argon2id$%'` → 0). Detail: `54-rust-idiom-hardening.md` **Part C** (§C1–§C8) + `50-tasks.md` Phase 7 (**T63 / T65 / T67 / T66**).

13. **Third verification pass (2026-10-22 (c)) — the gates were EXECUTED, not read.** A review pass re-ran the plan's own gates against the live tree and measured the lints instead of assuming them. **6 further corrections, 2 of them blocking:** (a) **B2's new grep gate contradicted B2's own prescribed fix** — it matched `unwrap_or_else`, which is used **benignly 6×** on the tree and is *not* a panic spelling, and `state.rs`'s documented fail-fast **is** `unwrap_or_else(|_| panic!(…))`, the exact line B2 tells the executor to write; the gate now matches `panic!`/`todo!`/`unimplemented!` with the ONE **boot-time** fail-fast explicitly allow-listed; (b) **T63's AC contradicted itself** — its grep included `\btime::`, which cannot be 0 hits because `src/lib.rs:155` uses the `time` crate, **required** by `tower_sessions::Expiry::OnInactivity` (T65 removes the *store*, not the `Expiry` call); (c) **T57 would not have pinned the toolchain in CI** — `dtolnay/rust-toolchain@stable` exports `RUSTUP_TOOLCHAIN`, which **overrides `rust-toolchain.toml`**, so the workflow is now in T57's Touch-only; (d) **`clippy::pedantic` is ~370 warnings, not 0** (measured) — `pedantic` is therefore **advisory** (CI adds `-A clippy::pedantic`; the measured debt is recorded for a follow-up), while `missing_docs`/`unreachable_pub` measured **0** and stay deny-level/blocking for free; (e) **T66 must bump `sqlx-cli`** with the driver (a 0.8.6 CLI cannot regenerate a 0.9 `.sqlx/` cache) — the pin lives in the workflow *and* `30-db-schema.md`; (f) `missing_docs` was proved to FIRE by appending an undocumented `pub fn`, and the "4 dead direct deps" wording was corrected to **3** (`time` is not dead). Detail: `54-rust-idiom-hardening.md` §"Second verification pass (2026-10-22 (c))" + `50-tasks.md` Phase 7.

## Constitution (global DoD, applies to every task)

* `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test` green; `cargo sqlx prepare --check --workspace --all -- --all-targets` green (single crate — flags are no-ops but the form is canonical everywhere); `.sqlx/` committed.
* TDD: failing test written first. No existing test deleted, skipped, or weakened to pass.
* Every data-mutating test asserts persistence via a **second read** (GET or direct sqlx `SELECT`), not just the mutation response.
* Contract changes only via spec task (update `20-api-contract.md` + `21-api-standard-shapes.md` + utoipa + `openapi.json` + typegen in same PR).
* Unknown JSON fields ignored (serde default, no `deny_unknown_fields`) to match Nest behavior — no global `ValidationPipe`, and the per-endpoint pipes use `transform:true` without `whitelist`, so unknown keys pass through and are dropped without rejecting. `axum-valid` (garde) hardening returns `400` (never 422 — parity with Nest's per-endpoint pipes on mutations except auth register/login, which had no pipes; see Amendments + `10-architecture.md`). garde extends the same 400 to auth inputs + GET query DTOs, which Nest mostly left unvalidated — a new strictness the frontend migration (T41*) must audit (pre-sanitize `?project_id=abc`, `?page=0`, undefined/garbage query params or accept the 400 as a surfaced bug).
* No `unwrap()/expect()` in request paths; no `sqlx::Error` text leaked to clients; no `format!`-interpolated SQL values.
