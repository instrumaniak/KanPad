The move transaction (`cards/routes.rs::move_card`) already retries a **same-card race** (bounded 5×) but NOT a MySQL **deadlock** (`1213`) or **lock-wait timeout** (`1205`), which the `SELECT … FOR UPDATE` + range-`UPDATE` pattern can produce under concurrent cross-column moves (the stable ascending lock order makes deadlock unlikely, not impossible).
