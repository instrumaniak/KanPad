# 30 — DB schema + migrations (MySQL 8.4, sqlx)

## Tables (12 app tables + 1 store-owned session table in the app DB + sqlx journal)

NO Nest-shaped session table in the baseline.
Session-table decision (2026-10-18 amendment): Nest's TypeORM table is `session` (bare `@Entity()` on `Session` → singular default, see `1778100000000-AddSessionsTable.ts`) in the **public** schema; the Rust store owns `sessions` **in the app database** (different table name, shape, and MessagePack codec). **No rename, no shared table, no row port.** Baseline creates only `sessions` (DDL verbatim from `MySqlStore::migrate()` with `.with_schema_name(<current DB>)` + `.with_table_name("sessions")`, verified by diff); Nest keeps its `session` table during cutover untouched; at cutover it is abandoned (rows ephemeral — drop or leave). Force-re-login is guaranteed by the new `SESSION_SECRET` + incompatible codec (old cookie fails HMAC → anonymous → 401). The sessions table is now per-database (not server-global), so it is fail-fast (`CREATE TABLE`, no `IF NOT EXISTS`) like the app tables. **Baseline amended in place (2026-10-19):** sqlx stores a SHA-384 of each migration's bytes in `_sqlx_migrations` and refuses to re-run an applied migration whose bytes changed (`VersionMismatch`), so a database migrated with the pre-2026-10-19 baseline carries a stale checksum — it must be dropped and re-migrated from the baseline. The baseline is a squash (the cutover always builds a FRESH database), so an empty target is unaffected; never hand-edit `_sqlx_migrations`. Runbook: `docs/data-migration-live.md` §"Baseline amendment (2026-10-19)".
IDs: all PK/FK `INT SIGNED` ↔ Rust `i32`, ceiling 2,147,483,647 — NO `UNSIGNED` upgrade in baseline (would diverge from TypeORM `int`; revisit via explicit 0002 if ever needed).
Cascade rule (implement ONE, DB-side): `Board.notes` currently double-cascades (`@OneToMany(cascade:true)` + `Note.board onDelete:CASCADE`) — baseline keeps DB `ON DELETE CASCADE` and records the Nest double-cascade as drift (Nest source is frozen; no Nest code changes — the rewrite simply does not repeat the shape). Same rule for `BoardColumn.cards`, which repeats the shape. `notes.user_id`/`tags.user_id` FKs (`ON DELETE CASCADE`) MUST be in baseline even though NO entity declares the relation (migration-only FKs — checklist catches these).

concurrency proof is single-node dense-order + no-loss, not strict serializability) + `IDX_cards_due_date(due_date)`; `labels` single `IDX_labels_user_id(user_id)` + `CONSTRAINT UQ_labels_user_name UNIQUE(user_id,name)`; Case-collision note: `utf8mb4_unicode_ci` makes `UQ_*_user_name` case-insensitive — `'Work'` vs `'work'` collide per user; decided ACCEPTABLE (matches app-level duplicate checks), document in API errors.
Baseline DDL rules: every `CREATE TABLE` spells `ENGINE=InnoDB DEFAULT CHARACTER SET=utf8mb4 COLLATE=utf8mb4_unicode_ci` explicitly (TypeORM emits bare `ENGINE=InnoDB`, inheriting DB defaults — drift source); temporal cols `created_at DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6)`, `updated_at DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6) ON UPDATE CURRENT_TIMESTAMP(6)`; NO `IF NOT EXISTS` on any table (fail fast — silent skips hide drift; `notes`/`tags`/`checklists` migrations used it, baseline strips it). The store-owned `sessions` table is also fail-fast now (per-database, no cross-process race); its DDL is verbatim from `MySqlStore::migrate()` with `.with_schema_name(<current DB>)` + `.with_table_name("sessions")`. strip `AUTO_INCREMENT=N` table options from dumps (nondeterministic checksums/diffs). CI asserts `SHOW CREATE TABLE` per table (engine/charset/collation + spot-check defaults).
Review checklist (T02 gate, blocks baseline sign-off): diff EVERY baseline `CREATE TABLE` col-by-col vs entity fields — catches ghosts (`username`, `projects.description`), migration-only FKs (`notes/tags.user_id`), default mismatches (`columns.position`, `due_date` precision); confirm NO Nest-shaped `session` table leaked in; confirm `sessions` DDL byte-matches `MySqlStore::migrate()` output with `.with_schema_name(<current DB>)` + `.with_table_name("sessions")`; confirm `view_mode`/`color`/`role` CHECK lists vs TS unions; confirm `tags` has no `updated_at`.

## Type mapping (TypeORM → MySQL → Rust)

`@PrimaryGeneratedColumn INT` → `INT AUTO_INCREMENT` → `i32` (read `last_insert_id()` as `u64`, then `i32::try_from` → `AppError::Internal` on overflow; never silent `as` cast — clippy `-D warnings` does not enable `cast_possible_truncation`); `@Column varchar` → same → `String`; `text/mediumtext` → same → `String` (list queries exclude via explicit column lists); `datetime` → `DATETIME(6)` → `chrono::NaiveDateTime` (never `DateTime<Local>` — server pinned UTC, see below); `bool/tinyint(1)` → `bool`; TS-union-as-varchar (`color`/`view_mode`/`role`) → `VARCHAR+CHECK` → Rust `enum + ToSchema` (never MySQL `ENUM`); `NULL` → `Option<T>`; `created/updated` → `DATETIME(6)` managed in SQL (`NOW(6)`), not app clock; session expiry (`sessions.expiry_date`) → `TIMESTAMP(6)`, written by the store — the app never touches it.

## Migration strategy: squash to one baseline, archive TypeORM

Do NOT replay 10 TypeORM files through sqlx (different journal: `typeorm_migrations` vs `_sqlx_migrations`, plus MySQL-DSL drift). Steps (T02): boot fresh MySQL 8.4 with `--default-time-zone='+00:00'` (compose `TZ=UTC` + `command: --default-time-zone='+00:00'`) → run Nest `migration:run` to tip → `mysqldump --no-data` → hand-clean into `migrations/0001_baseline.sql` per rules above (one `CREATE TABLE` per app entity, explicit FK/index/CHECK names, ghosts dropped, PLUS the store-owned `sessions` DDL verbatim in the app database — NO Nest `session` table) → review checklist → `sqlx migrate run` on EMPTY db + `sqlx migrate info` (pending=0) → e2e (reorder tx, cascade deletes). Archive `backend/src/migrations/*.ts` to read-only `backend/src/migrations.archive/` + PRUNE `typeorm-registry.ts` (confirm filename at implementation) (`migrations` array emptied, entities stay until cutover); CI runs `migration:show` pre-cutover to prove TypeORM tip matches the baseline source modulo the documented-deviations list, and fails if `src/migrations/*.ts` changes after archive. New changes → `0002_*.sql` via `sqlx migrate add` (`-r` gives `<v>_name.up.sql`/`.down.sql` pair — boot migrator runs `.up` ONLY, `.down` is manual `migrate revert` material). Prod cutover is blue-green ONLY (CHOSEN: dump-restore-into-baseline-migrated staging, then promote staging to prod — hand-`INSERT` into `_sqlx_migrations` is REJECTED: sqlx 0.8 checksums are version-internal SHA-384 over file bytes, brittle to hand-compute; and `migrate run` on the non-empty Nest DB is UNSUPPORTED by design since `0001` has no `IF NOT EXISTS`). Ghost columns need an explicit transform at restore time: a prod data-only dump still emits `INSERT INTO users (…,username,…)` / `INSERT INTO projects (…,description,…)` plus `session` + `typeorm_migrations` rows, which the baseline (no ghost cols, no Nest tables) rejects — so the restore step MUST use `--ignore-table` for `session`/`typeorm_migrations` and strip ghost columns (column-list rewrite or `sed` on the dump; verified in T02b staging proof). Full runbook with downtime/delta handling lives in `31-live-unicode-migration.md §31.5`; existing prod's TypeORM journal is abandoned, never converted row-by-row.

## sqlx workflow

Toolchain PINNED `cargo install sqlx-cli --version 0.9.0 --no-default-features --features mysql,rustls` (**T66: the CLI version moves with the driver — a 0.8.6 CLI cannot regenerate or validate a 0.9 `.sqlx/` cache.** The 0.8.6 pin was the pre-T66 value) (same version in CI image; `migrate info` confirmed present in 0.8 — gates pending/applied + checksums). **2026-10-22 (c): the CLI version moves with the driver — T66 (sqlx 0.9) bumps this pin to the 0.9 line in this file AND in the CI workflow; a 0.8.6 CLI cannot regenerate or validate a 0.9 `.sqlx/` cache.** Files `migrations/<unix>_<snake>.sql` (non-matching names ignored). App boots `sqlx::migrate!("./migrations").run(&pool)` — `.up` files only when reversible pairs exist. Time: `mysqld --default-time-zone='+00:00'`, app uses `NaiveDateTime`/`NOW(6)` — no session `SET time_zone`, no `DateTime<Local>`. Pool `MySqlPoolOptions{max 10-20,min 1,acquire 5s,idle 600s,lifetime 30m,test_before_acquire(true)}` — ONE pool via `State`, never per-request. `QueryBuilder` for filters/`IN(separated())`/pagination (macros need literal SQL); `push()` needs trailing spaces; sort keys whitelisted `match`, never `format!` values. LIKE patterns built in Rust + `push_bind` only (never `push` of user input); escape `%`/`_`/`\\`. One shared WHERE-builder helper builds the filter once and reuses it for both `COUNT` and page `SELECT` (prevents filter drift). `Page` lists use `COUNT(DISTINCT id)` where joins fan out (notes×tags). Multi-row inserts return first id only — insert one-by-one or compute range. Keep txs short (begin → 2–5 stmts → commit); lock reorder rows in STABLE `(column_id,position)` order (`SELECT ... FOR UPDATE ... ORDER BY column_id, position`, range `UPDATE`s issued in ascending `column_id` order — `min(column)` first; opposite order deadlocks on cross-column swaps) (deadlock avoidance; consider `READ COMMITTED` for the move tx to reduce MySQL gap-lock deadlocks under default `REPEATABLE READ`); no `pool.acquire()` inside tx, no network `.await` while holding tx.
