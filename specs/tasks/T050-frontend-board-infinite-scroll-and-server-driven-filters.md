## Implementation Steps

1. **Column cards:** initial board columns fetch with `embed_limit=10`. Column card hydration uses infinite scroll via IO sentinel in same scroll root; **page size is 20 (locked)**. Dedupe by id on merge into `['columns', boardId]`.
2. **Notes side panel:** convert `useBoardNotes`/sidebar to infinite query `limit=20`, `board_id` filter, IO sentinel in the same scroll container as the notes list (current sidebar uses `ScrollArea`/shadcn scroll area—place sentinel inside that scroll root and wire `hasNextPage`/`fetchNextPage`). Preserve create/edit/delete invalidation.
3. **List view:** use the board cards list endpoint `GET /api/v1/boards/{boardId}/cards` with `useInfiniteQuery`, **20/page (locked)**, server sort/order/filter/search in query key. IO sentinel triggers next page. Virtualized rendering remains.
4. **Server-driven filters:** search input debounce updates query params/state; filter chips/dropdown produce server filter params. Query keys include filter/search/sort. Remove `filterColumnsByTitle`/`filterColumnsByFilters` as authoritative data filters (keep only if needed for pure UI helpers, document). If any helper remains, it must not be treated as the source of truth for server results.
5. **DnD under filters (amended by T053):** card drag/reorder/cross-column move are allowed when the drop resolves to a safe visible anchor (anchor-based move semantics; no ambiguous position writes against hidden cards). Cross-column anchor/append moves include `column_id`; same-column anchor moves may omit it. Sort-by-date and Move All Cards remain disabled/guarded. Keyboard DnD follows the same anchor/ambiguity rules. Blocked ambiguous drops (no visible anchor, unloaded matching tail, hidden-only target, unknown `matching_cards` for ambiguous end/container) give a neutral/default non-assertive toast (title `"Can't drop here while filters are active."`) + persistently mounted polite `aria-live` feedback (`data-testid="dnd-blocked-status"`, `role="status"`, `aria-live="polite"`, repeated announcements for identical drops), no focus steal, no mutation. **Locked UX expectation (minimum):** explicit disabled/blocked affordance and user-visible copy for sort/move-all (titles "Clear search and filters to sort cards" / "Clear search and filters to move all cards"; board banner "Sorting and move-all are disabled while search or filters are active. Card drag and drop is available for visible cards."). Implement consistently across board view and list view where drag/move/sort affordances exist. Hidden-gap consequence is documented: clearing filters may reveal hidden cards around the moved card.
6. **Cache coherence:** mutations invalidate `['columns', boardId]`, board-cards infinite query, notes board infinite query as applicable. No dual DnD cache. Reset infinite accumulations on filter/sort/search change.
7. **A11y:** `aria-live` loading/end/error status, accessible load-more/retry fallback, focus not lost on append, sentinel in same scroll root.

## Constraints

- Server-side search/filter is authoritative; no silent incomplete client-only success.
- React Query: query keys include filter params; dedupe by id; targeted invalidation; no `waitForTimeout` in e2e.
- No dual DnD cache; canonical board cache remains `['columns', boardId]` for unfiltered DnD/render.
- Card DnD under filters uses anchor-safe behavior (T053) instead of a blanket disable; sort/move-all remain disabled/guarded. No ambiguous position writes against hidden cards.
- IO sentinel must be in same scroll root as virtualized/list scroll container.

## Acceptance Criteria

- [ ] Board view loads 10 cards/column initially (`embed_limit=10`); infinite scroll loads remaining cards in **20/page** chunks without duplicates.
- [ ] Board notes side panel loads 20 notes initially; infinite scroll loads all remaining notes (sentinel in notes scroll root).
- [ ] List view uses the board cards list endpoint (`GET /api/v1/boards/{boardId}/cards`) with **20/page** infinite scroll and server-side sort/filter/search.
- [ ] Search/filter drives server queries; changing filters resets accumulation and shows server-confirmed results.
- [ ] Sort-by-date and Move All Cards are explicitly disabled/guarded while filters/search active with clear user-visible affordance/copy; card drag/reorder/cross-column move is allowed for visible anchors (T053) with blocked-drop feedback for ambiguous drops (neutral/default non-assertive toast + persistently mounted polite `dnd-blocked-status`, repeated announcements, no focus steal, no mutation).
- [ ] Loading/error/end states are accessible; unit tests cover key behaviors.
